# Bug Fixes — Post-Sprint 5/6

**Date:** 2026-06-02

## Fixes

### Stripe key crash on startup

- `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` was required in the Zod env schema but absent from `.env.local`
- Made it `.optional()` and guarded `loadStripe()` with a null check in `checkout-flow.tsx`

### No "Add to cart" button on product listing

- `ProductCard` was a plain `<Link>` with no cart action
- Added `AddToCartButton` inside a `<div onClick={(e) => e.preventDefault()}>` wrapper to block link navigation on click

### All products showing "Rupture" (out of stock)

- Seed never created `InventoryItem` records — `inventoryItems.some(...)` on empty array returns false → `inStock = false`
- Added warehouse (`FR-PARIS-01`) + inventory items to `seed.ts` (50 units for accessories, 3 for robots)
- Used `findFirst` + conditional create/update instead of `upsert` to avoid Prisma 5 null composite key error

### CI: Deploy API job failing

- `RENDER_DEPLOY_HOOK_URL` secret was not set; curl returned empty response; Python JSON parse crashed
- Render auto-deploys via GitHub integration — replaced the curl step with an echo no-op

### OAuth redirect lost after login

- After Google/GitHub OAuth, `auth/callback/page.tsx` always redirected to `/` ignoring any intended destination
- Admin layout redirected to `/compte/connexion` without `?redirect=` param
- Fix: admin layout passes `?redirect=${pathname}`; connexion page saves redirect to `sessionStorage` before OAuth redirect; callback page reads and clears `sessionStorage` after auth

### Admin layout blocked SUPER_ADMIN role

- Layout checked `user.role !== 'ADMIN'` only — SUPER_ADMIN users were redirected away
- Fixed to allow both `ADMIN` and `SUPER_ADMIN`

### Hydration error on navbar cart badge

- `<motion.span>` inside `<button>` for cart count rendered on client (Zustand initialized) but not on server (count = 0)
- Added `mounted &&` guard — badge only renders after client hydration, matching server output
